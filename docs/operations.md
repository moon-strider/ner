# Operations

## Deployment boundary

Use this as a single-owner service on a trusted network. Set `NER_API_KEY` before
sharing access and use a TLS reverse proxy for remote traffic. All authenticated
callers share configuration storage, cache, and provider credentials; this is not
a multi-tenant authorization system. Use `ALLOWED_MODELS` to restrict spending
and Prometheus label cardinality when callers should not select arbitrary models.

`/v1/health`, `/v1/ready`, `/metrics`, `/docs`, and `/openapi.json` remain public.
Restrict these at the gateway if needed. The repository's container stack binds
published ports to localhost. It does not create a public deployment.

The request body limit bounds each body, and the provider limiter bounds upstream
calls. For exposed deployments also set proxy rate limits, connection limits,
request deadlines, and storage quotas. The Docker command sets Uvicorn's
`--limit-concurrency 200`. Its overload response is generated by Uvicorn before
the application, so the application's error envelope does not apply to it.

Run one worker by default. Cache, token bucket, circuit breaker, and metrics are
per process. Adding workers multiplies these limits; no cross-process cache,
transactional multi-worker PATCH, or distributed rate limiting is provided.

## Containers

```bash
cp .env.example .env
# Edit provider settings as needed.
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8000/v1/ready
```

The image runs as a non-root user and installs a built package into its virtual
environment. Builder and runtime use the same Debian release. The build context
contains only package metadata, license, README, and source code: no credentials,
model weights, local databases, or development artifacts.

SQLite is stored in the `ner-data` named volume at `/app/data/configs.db`.
`docker compose down` preserves volumes. `docker compose down -v` deletes them;
use that only when intentionally discarding all stored configs and monitoring data.
For a manual `docker run`, mount a volume at `/app/data` yourself.

A model server on the host needs to be reachable from the container. Set
`LLAMA_CPP_BASE_URL=http://host.docker.internal:8080/v1`; the hostname is mapped
with `host-gateway`. On Linux, a server bound only to host loopback is not reachable
through that bridge. Bind the model to an appropriate host interface, protect it
with its own API key/firewall, or run the NER service directly on the host.
Never set the model server port equal to the NER service port.

Readiness opens and queries the config table. Startup fails if storage cannot be
initialized. Readiness does **not** call the LLM, check provider credit, or assess
model availability. Use `scripts/smoke.py` for an upstream check.

## SQLite and backups

SQLite uses WAL mode and a serialized persistent connection. Configs survive
process restarts. `CONFIG_DB_PATH=:memory:` is supported for temporary testing;
its contents disappear when the store closes.

Create backups through SQLite's backup API or the `sqlite3 .backup` command. Do
not copy only the `.db` file while writes are active and ignore its WAL companion.
A stopped-service copy of the database and its companion files is another option.
Keep backups private: custom prompts and few-shot examples may contain sensitive data.

## Monitoring

```bash
docker compose --profile observability up -d --build
```

| Component | URL |
| --- | --- |
| Service readiness | `http://127.0.0.1:8000/v1/ready` |
| Prometheus | `http://127.0.0.1:9090` |
| Grafana | `http://127.0.0.1:3000` |

Grafana uses user `admin`; set `GRAFANA_ADMIN_PASSWORD` before the first start.
The local fallback is `local-development-only`. Changing the variable after an
existing Grafana volume is initialized does not reset its stored password.
The provisioned datasource UID is `prometheus`; dashboard UID is `ner-service-overview`.

Service metrics include:

- `ner_extraction_total` and `ner_extraction_latency_ms`: single and batch items,
  including cache hits and service-level failures.
- `provider_errors_total`: service exceptions by type (including validation/storage failures).
- `ner_tokens_total`: validated provider usage from successful extractions,
  including repair attempts. Cache hits do not increment it.
- `ner_cache_total`, `ner_structured_output_retries_total`, and `ner_circuit_breaker_total`.
- `ner_estimated_cost_usd_total`: optional estimate from successful extraction usage.

Failed extractions may also have consumed tokens; these counters are not a complete
billing ledger. Model failures without token usage cannot be priced. Metrics are
process-local and aggregate across app instances in that process; error metrics
use the default model if config resolution did not complete.

Set `OTEL_ENDPOINT=http://collector:4318/v1/traces` to export spans. Settings are
loaded before instrumentation; shutdown closes the exporter. Do not put personal
text into request IDs. Model error bodies and entity surfaces are not returned
in public errors; internal unexpected exceptions still go to operational logs,
which should remain access-controlled.
